# Styles — app.css, theme.css, icons.css

All styling is plain CSS in `theme/assets/` (no preprocessor, no framework). Anvil serves the files under `_/theme/...` with `?v=` hashes kept in `anvil.yaml` by `python tools/assets.py` (run it after any change in `theme/assets/`).

| File | Lines | Role | Edit by hand? |
|---|---|---|---|
| `theme/assets/app.css` | ~1,614 | Design tokens (light + dark), the design kit, shared `ui-*` components, every page's styles, the Anvil role layer, and every game (`.cft-*`) and wiki (`.wk-*`) style | Yes |
| `theme/assets/theme.css` | 33 | Inlined by Anvil into the page before the app loads: page background (light/dark) and the loading spinner drawn as the app icon | Mostly no: the `loader:start ... loader:end` block is written by `APP_MAKER/tools/loaders.py`; never write Anvil's theme-colour token pattern (percent sign, `color:`, a name, percent sign) in this file, Anvil substitutes it |
| `theme/assets/icons.css` | 58 | Mask-image icons `.ic.ic-NAME` and roles `ic-NAME` on Anvil Buttons/Links | No: generated by `tools/build_icons.py` from `UI.ICONS` in `app-kit.js` |

## 3. Naming conventions

- **Prefix per area:** `.cft-*` game engine DOM (cft-ui, cft-cine, cft-debug and the other engine modules), `.wk-*` balance wiki, `.ui-*` app shell components, `.lp-*` landing, `.lf-*` life, `.qs-*` quests, `.al-*` album, `.rk-*` ranks, `.au-*` auth, `.pf-*` profile, `.ad-*` admin, `.cf-*` shared page pills (`_cft.html`), `.anvil-role-*` Anvil component roles, `.ic-*` icons. <!-- doc-check: skip -->
- **JS hooks are `data-*` attributes, styles are classes.** cft-ui queries `[data-money]`, `[data-feed]`, `[data-pw="water"]`...; keep classes for looks so CSS refactors do not break the engine. Exception: some state classes are toggled by JS (`.on`, `.sel`, `.pop`, `.show`, `.out`, `.go`, `.in`, `.low`, `.bump`, `.touch`).
- **Modifiers are bare second classes:** `.cft-btn.primary`, `.cft-btn.sm`, `.cft-banner.done`, `.cft-loot.q3`, `.cft-cine-card.title`.
- **Section comments** start with `/* ===== <area> (<file>, <date>)` so `grep -n "/\* =====" theme/assets/app.css` lists them. New feature CSS goes in a new block at the end with that header, unless it belongs to an existing block.
- Deliberate exceptions to the design check are marked `/* design-ok: <rule> (why) */` on the rule.

## 4. Design rules (from `.claude/skills/cityfuntime/SKILL.md` and `APP_MAKER/design/README.md`)

- **"Sticker City":** paper `#fff6e9`, ink `#1f1a3d`, grape `#6b4eff` (brand), gold `#ffc21f` (accent), pink `#ff5c8a`, mint `#20c997`; dark background `#16122e`. Fredoka for headings, Nunito for body. Chunky 2-3 px ink outlines and hard offset shadows (`4px 4px 0` / `6px 6px 0`). Emoji everywhere is deliberate.
- **The game HUD is always light:** `.cft-*` styles use literal colours (`#fff`, `#1f1a3d`) rather than the dark-mode tokens. Pages and the wiki use the tokens and must work in light and dark (both token blocks).
- **Mobile-first:** every page fits 390 px with no sideways scroll; the game has touch controls (`.cft.touch`). Touch targets >= 44x44 px on phone.
- **Four corners:** HUD information only in the four corners; nothing in the middle 40-60% column or row (enforced by `game_test.py --wild`). Corner columns capped at 40vw/40vh.
- **Contrast:** text >= 4.5:1 (large 3:1), icons/focus rings >= 3:1. Focus-visible styles on every control (`outline: 3px solid #ffc21f` pattern in the cine skip button).
- **Motion:** use the kit tokens (`--ease-*`, `--dur-*`), animate only `transform`/`opacity` where possible, never `transition: all`, no animation on frequent keyboard actions; every new animation gets a `@media (prefers-reduced-motion: reduce)` rule (fewer and gentler, keep short confirming fades).
- **Type:** body 16 px minimum on pages; the HUD uses 15 px base by design; `text-wrap: balance` on headings.
- The design check (`APP_MAKER/tools/design_check.py`, run by `python tools/check.py`, never fails the run) and `python -I tools/ui_test.py --only design.js` report the "AI-made tells" and craft-floor issues; fix or mark `design-ok`.

Inside `.cft-layer`, later overlays stack above earlier ones by DOM order (no z-index needed). A cinematic scene hides the HUD via `.cft[data-cine] > :not(.cft-layer):not(.cft-canvas)...{opacity: 0}`, so new top-level `.cft` children are hidden during scenes automatically; add them to that `:not()` list only if they must stay visible.

## 6. How to change styles safely

1. Find the block: `grep -n "/\* =====" theme/assets/app.css`, or search the class used in the JS (`grep -n "cft-wslot" theme/assets/*.js`).
2. Edit; keep LF line endings.
3. `python tools/assets.py` (new hash), `python tools/check.py` (design check note).
4. Look at it: game `python -I tools/live/game_test.py --campshots DIR` (HUD desktop + phone) or the feature's `--*shots`; pages `python -I tools/ui_test.py --shots DIR` (desktop + phone, light + dark); a11y `--only a11y.js`.

Review checklist for style diffs:
- [ ] Both dark token blocks updated when a token changes; game HUD stays light.
- [ ] No HUD element in the middle column/row; works at 390 px portrait and landscape phones.
- [ ] New animation has a reduced-motion rule; no `transition: all`.
- [ ] z-index fits the ladder above.
- [ ] Selectors match classes that exist in the JS/templates (no dead rules for renamed classes).
- [ ] `theme.css` and `icons.css` not hand-edited outside allowed parts.
